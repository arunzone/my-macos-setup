
## Command execution rule
Before asking to run ANY command, explain it in three one-line entries for fast review:
- **why:** the purpose
- **what:** what the command does
- **impact:** system-level and user-level effects

Apply this to every command in every project, no exceptions.

## Code-change proposal rule
Before presenting ANY code change, diff, or implementation proposal, prepend a brief rationale covering all four points:
1. **Task** (high level): the problem being solved.
2. **This suggestion:** what the change does, concretely.
3. **Relevance:** how it connects to the problem.
4. **Why best:** justification from mature devops / software-engineering practice.

Never present code without this framing. Applies to every project, no exceptions.
